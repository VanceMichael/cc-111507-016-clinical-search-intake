# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息。structured 沿 `/fhir` 采集 searchset，可选 `query`（字符串或对象，作为筛选参数附加到初页）和 `filter`（同义的筛选别名）。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

## 结构化检索范围

- 初页固定为 `/fhir?page=1`，请求中携带的 page 会被忽略并记入 coverage；后续页只跟随该页 `Bundle.link[relation=next]` 的 URL，沿用来源给出的查询上下文（如 token）。只访问网关本源内链接，指向外部的 next 记为 unsafe-next-link 并停止。
- `entry.search.mode` 为 match 的条目形成匹配资源，include 形成附带资源，outcome（或 OperationOutcome 资源）写入 issues 而不进入 records；缺 mode 或未知 mode 记为 unknown，单独计数，不计入任何资源集合。issues 中另以 `source-outcome` 保留来源 severity 和原文 issue。
- 资源身份为 `resourceType/id/meta.versionId`；records 按身份去重，同一身份跨页重复只保留一条并记录 alsoSeenOn。同一身份同时以 match 和 include 出现时按 match 计，重复的附带条目单独计入 `duplicateIncludeEntries`，不会形成新的服务对象；`counts.matchObjects`/`includeObjects` 按类型/id 统计服务对象数。
- 引用关系逐条写入 `evidence.relationships` 与 record.basis：`ORG/id/_history/N` 只精确匹配到该版本；未指定版本的引用只有在已采集身份唯一时才解析为 `unversioned-single-candidate`，否则为 `ambiguous`，不会任意替换成历史版本；`fullUrl`（urn 别名）只在本次已采集条目内解析；外部、contained 或无法解析的引用保留原文并记 warning。
- total 只作来源声明，与唯一匹配资源数不一致记 `total-mismatch`；next 循环、重复页（相同分页字节）、读取失败、分页上限、未约定的 extension 都会进入 issues 和 coverage.gaps，此时 complete 为 false。只有入口可解释、全部页读完且 issues/gaps 为空时才写 complete。

领域输出约定：records 中 mode 保存 match/include；outcome 只在 issues；资源按类型、id与版本去重，匹配身份与附带身份分开。issues 的 severity 保留来源 severity 映射（error/fatal 记为 error，information 记为 information，其余为 warning）。
