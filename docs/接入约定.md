# 接收接口

服务通过本机来源网关取件；服务 URL 和来源 URL 不相同。`createService({dataDir, scenario})` 返回 baseUrl、gateway.baseUrl、store 及异步 close()，测试可直接启动，不依赖固定端口。所有用户可见错误采用中文。

- `GET /health`：进程健康。
- `GET /v1/source`：当前来源描述及 entry。
- `POST /v1/intakes`：JSON 对象，mode 为 raw 或 structured；其他字段按来源需要可含 filter、version、region、tables、view、query、client、basisPath。raw 只领取入口文件并记录元信息。structured 按 FHIR R4 searchset 采集：请求上下文写入 `coverage.request` 与 `coverage.pagination.initialUrl`，其后只跟随来源 `Bundle.link[next]`。
- `GET /v1/receipts` 和 `GET /v1/receipts/{id}`：读取本地收件结果。

收件文件位于 DATA_DIR/receipts，原文位于 DATA_DIR/blobs，以 SHA-256 寻址。原始接收状态为 received；结构化收件结果的 state 使用 complete、partial、rejected，records 保存领域记录、issues 保存可定位问题、coverage 解释本次范围和完整性、evidence 保存来源字节、版本或关系依据。不能在仍有未知缺口时写 complete。正常收件返回201，语法错误400；来源部分失败可形成 partial 收件，完全无法解释可形成 rejected，不要求通过抛出异常丢掉原文。

结构化记录可增加领域字段，但来源定位必须可追溯，稳定身份不得仅使用数组下标。接收后查询返回相同记录；新的实例打开相同 DATA_DIR 仍可查询既有结果。请求只有本机合成来源，不接受任意互联网地址。

领域输出约定：records 中 mode 保存 match/include；outcome 只在 issues；资源按类型、id与版本去重，匹配身份与附带身份分开。

## 结构化采集语义

- 每个 records 条目带 `basis`（mode、原始 mode、fullUrl、页码、条目下标）和 `locations`（全部出现位置）；同一 `resourceType/id/meta.versionId` 在不同页面重复出现时合并为一条，`occurrences` 记录出现次数，`coverage.counts.duplicateEntries` 与 `crossPageDuplicates` 分开统计，不把附带资源重复页算作新增服务对象。
- `search.mode` 为 match/include 的条目才进入 records；outcome 只转写为 issues；缺失或无法识别的 mode 放入 `coverage.unknownEntries` 并计入缺口，不冒充命中。
- 分页只使用来源给出的 next 链接；解析失败、指向来源以外、循环、重复页面、页数超限、页面读取中断均记为 issue 与 `coverage.gaps`，`coverage.pagination.completed` 为 false，收件最多为 partial。声明式 `total` 只记录在 `coverage.total`，不作为完整性依据。
- 引用关系逐条写入记录的 `references`：相对/绝对引用按 `resourceType/id` 解析，版本化引用必须精确匹配 `meta.versionId`，缺少版本的引用在同一 id 只有一个版本时解析，多版本时记为 `ambiguous-unversioned` 而不会自行选择；urn 别名按本结果集 fullUrl 解析，别名冲突不猜测；指向来源之外的引用不解析。解析失败按严重程度写入 issues，warning 及以上进入 gaps。
- `evidence.pages` 保存每页 URL、状态、ETag、SHA-256 与是否可用；原始字节均写入 blobs，包括读取中断时已收到的片段。
- 局部读取失败、来源 OperationOutcome 与 HTTP 错误都保留 issue，不会因为取到数页就宣称筛选范围完整。
